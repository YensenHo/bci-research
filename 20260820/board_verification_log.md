## 8. 实验规范修复（train.py，Hermes↔Codex 辩论产物）

Codex 审查发现 `train.py` 用 eval 集**同时**做早停验证与最终测试（无独立 hold-out，存在选择偏差 → 76.39% 略乐观）。已修复：
- 加 `--val-split`（默认 0.15）：从训练集划 hold-out 做早停，eval（E 会话）只做一次 final test，消除测试集泄露。
- 加 `--hbc-aug`：训练时 HBC 链路噪声增强（5bit 量化 + 信道 AWGN），final test 报告「干净 vs HBC噪声」两个准确率，验证「约束驱动鲁棒解码」。
- 待数据重下后重训，报严谨的 cross-session final test 数字。

## 9. 重训结果：hold-out 修复 + 约束驱动鲁棒解码验证（2026-08-20）

数据重下（curl 断点续传 18/18 完整）→ 预处理（train/eval 各 1296）→ 重训。

**① hold-out 修复验证（消除早停选择偏差）：**
- 旧：eval 集同时做早停 + 最终测试 → 76.39%（略乐观）
- 新：train 划 15% hold-out 做早停，eval（E 会话）只测一次 → **final test 干净 75.00%**
- 差异 −1.39pp，证实早停选择偏差（Codex 抓对了）

**② 约束驱动鲁棒解码（HBC 噪声增强训练）：**

| 版本 | final test 干净 | final test HBC噪声 | 噪声下下降 |
|---|---|---|---|
| 基线 | 75.00% | 74.46% | 0.54pp |
| +HBC噪声增强（--hbc-aug）| **76.16%** | **76.23%** | **−0.08pp** |

**结论**：训练时注入 HBC 链路噪声（5bit 量化 + 信道 AWGN）作增强，模型在噪声下从「下降 0.54pp」变成「几乎零损失（−0.08pp）」，且干净精度 +1.16pp（增强起正则化作用）。**「约束驱动鲁棒解码」验证成功**——不是换新模型，而是把 HBC 链路约束纳入解码训练。

**③ per-subject（基线，hold-out 早停）**：均值 **75.00% ± 12.03%**（61.11%~95.83%），与 final test 一致，被试间方差大但均值稳定。

## 10. 新权重部署上板（噪声增强模型 76.16%）

- 导出 C 权重（1650 参数）→ Mac 上 `verify_c_infer.py` 验证 C vs PyTorch 一致性：**logits 误差 8.24e-07，20/20 一致**（BN 折叠正确）。
- 交叉编译（zig 0.13，arm-linux-musleabihf 静态）7 个二进制 + `eegnet_infer` → push 上板。
- 板载验证：

| 项 | 旧权重 | 新权重（76.16%） |
|---|---|---|
| CPU 单次前向 | 18.5ms | **23.2ms** |
| 闭环（realtime_throttle 20窗）| 85% / 26.5ms | **90% / 31.5ms** |
| 端到端（benchmark 100窗）| 81% / p99 65ms | **84% / p99 64.2ms** |

- ⚠️ 诚实记录：新权重 CPU 前向 23.2ms（旧 18.5ms，+26%）。差异可能来自编译版本（zig 0.13 vs 旧版）或噪声增强训练后的激活分布（ELU exp 计算次数），**均在 2s 窗口的实时余量内（~86×），不影响闭环**。根因待查（如需还原 18.5ms，可对比编译 flag）。
