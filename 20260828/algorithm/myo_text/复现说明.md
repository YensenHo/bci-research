## 1. 三个模块的职责与部署位置

| 模块 | 职责 | 部署位置 | 状态 |
|---|---|---|---|
| `finger_classifier.py` | CNN-BiLSTM-Attention 手指分类（8 指 softmax） | **端侧（RV1106）** | 结构完整，预留 SNN 接口 |
| `qwerty_mapping.py` | QWERTY 指法→候选字母/候选词（home-row 先验） | 端侧或上位机（纯逻辑） | 完整 |
| `t5_reconstruct.py` | T5-base 约束束搜索句子重建 | **上位机（手机/边缘/云端）** | 骨架，依赖 transformers |

数据流（split-execution，与论文一致）：

```
sEMG 击键片段(32ch) ──[端侧]──> 手指分类(8类) ──[QWERTY映射]──> 候选字母/候选词
                                                                    │
                                          （HBC 回传候选词，不回传原始肌电）
                                                                    ▼
                                          [上位机] T5 约束束搜索 ──> 完整句子
```

## 2. 数据预处理步骤（emg2qwerty → 1s+1s 击键片段）

### 2.1 数据集获取

- 数据集：**emg2qwerty**（Meta Reality Labs / Sivakumar et al. 2024, arXiv:2410.20081）
  - 规模：108 人 / 1135 会话 / 346 小时；双侧前臂 **16ch×2 = 32 通道** sEMG；
    带逐击键时间戳标注；QWERTY 触摸打字。
  - 官方仓库：`https://github.com/facebookresearch/emg2qwerty`
  - 论文：`https://arxiv.org/abs/2410.20081`

- **下载方式（含 GFW 影响说明）**：
  ```bash
  # 官方直链（S3，非 HuggingFace；已实测可达，HEAD 200 OK）：
  #   https://fb-ctrl-oss.s3.amazonaws.com/emg2qwerty/emg2qwerty-data-2021-08.tar.gz
  # 实测大小：Content-Length = 308,382,645,571 B ≈ 287 GiB（~308 GB，单文件全量 tar.gz）
  # 断点续传：curl -C - -O <上面的 URL>
  # 注意：数据在 AWS S3，不在 HuggingFace，HF_ENDPOINT 镜像对其无效。
  ```
  > **本复现不要求本机下完全量数据**。全量 287 GiB 远超 50GB 阈值，官方无子集下载接口，
  > 30 被试子集（MyoText 所用）需先解压全量才能筛出。详见
  > `手指分类_数据探查与复现说明.md` §1（含 HDF5 结构逐字段核对）。

### 2.2 预处理流程（论文描述，待落地）

1. **读 HDF5 日志**：emg2qwerty 以 HDF5 记录每会话的 sEMG 流 + keystroke 时间戳。
2. **击键事件切段**：对每个击键事件，切出 **击键前 1s + 击键后 1s** 的时间对齐片段
   （含预备 + 残余肌电活动），32 通道保持原始分辨率。
   - 采样率需按数据集实际标定（emg2qwerty 常见 2000Hz，代码默认值见
     `FingerClassifierConfig.fs_hz`，**需实测核对**）。
3. **打手指标签**：每个字母按标准 QWERTY 指法映射到 8 指之一（不含拇指），
   用 `qwerty_mapping.LETTER_TO_FINGER` 完成（见反向映射）。
4. **归一化/滤波**：基线去除、带通滤波（论文未细述参数，需按 emg2qwerty 基线
   做法补全——常见 20–450Hz 带通 + 50/60Hz 工频陷波）。
5. **被试筛选**：论文最终取 **30 名被试**（从 108 人中按多样性与算力可行性筛选）。
6. **划分**：5-fold CV（跨被试内随机划分）与 LOUO（留一被试）两套评估协议。

### 2.3 预处理脚本位置

> 预处理脚本已落地：`preprocess_emg.py`（本目录）。职责：读 HDF5 会话 → 击键切段
> （前1s+后1s，32ch 原始分辨率）→ 8 指标签 → 输出 `npz`（`X (N,1,32,4000)` + `y (N,)`）。
> 含 mock 会话自检（不依赖真实数据），并复用 `qwerty_mapping.LETTER_TO_FINGER` 打标签。
> 配套的轻量 CNN（`finger_cnn.py`）与 LIF 化训练（`train_lif_finger.py`）见
> `手指分类_数据探查与复现说明.md`。

## 4. 局限说明（论文自述 + 本复现客观局限）

### 4.1 论文自述的局限

1. **跨被试泛化是最大瓶颈**：基线跨被试 CER 高达 51.78%；MyoText 的 LOUO 手指
   分类也掉到 81.4%。「无标定的跨用户泛化」是开放问题。
2. **强依赖语言先验**：去掉语言模型后精度大幅退化（11.28%/55.38%），信号本身
   信息量不足以单独支撑高精度打字。
3. **sEMG 固有噪声/漂移**：电极位置、肌肉疲劳、个体解剖差异导致跨会话/跨用户不稳定。
4. **数据依赖大**：仅基于 emg2qwerty 单数据集，跨数据集泛化仍是初步。
5. **非实时、无速度指标**：离线评估，未证明在线实时打字可行性。

### 4.2 本复现的客观局限（务必对外如实说明）

1. **无官方代码、无官方权重**：三模块为从零骨架，权重需自行训练/微调。
2. **数据未落地**：emg2qwerty 尚未下载/预处理，训练与评测均为待办。
3. **架构细节以论文文字推断**：CNN 层数/通道、LSTM 隐层、注意力形式、T5 微调
   损失、约束束搜索的具体约束形式等，论文未给超参清单，本骨架取「合理默认值」，
   需实测调参对齐。
4. **SNN 接口为占位**：`activation='spike'` 是可运行占位（软阈值激活），**不是**
   真实脉冲网络；真实 ANN→SNN 转换需引入 snnTorch/spikingjelly 并做时间步展开
   + 阈值标定。
5. **T5 依赖未装**：`transformers` 当前环境未安装，`t5_reconstruct.py` 采用懒加载，
   需在上位机 `pip install transformers sentencepiece` 后才有真实推理能力。
