# 知识蒸馏框架总结（BCI 项目 · 2026-10）

> 项目里「蒸馏」是唯一稳定复现的强正结果方向。本文档把它的协议、结论、端侧落地、坑、资产
> 系统化，作为可复用框架（后续任何「蒸馏到新任务/新架构/端侧」都照此走）。

---

## 0. 一句话定位

让**大模型（teacher）**把「软标签」里的 dark knowledge 传给**端侧小模型（student）**，
使小模型在**低标注预算**下涨点 **+5~7pp**，且能与**类脑化（LIF）**兼容、能**端侧逐位一致**部署。
这是「端侧受益于蒸馏」的完整闭环，已跨任务（8ch 二分类 → 22ch 四分类）、跨架构（EEGNet → EEG-TCNet）、
跨激活（relu → LIF）三重验证。

---

## 1. 蒸馏协议（统一配方，跨任务复用）

| 要素 | 约定 |
|---|---|
| **师生对** | teacher 大容量 + student 小容量，**同架构族**（保证 relu/LIF 对比干净） |
| **软标签** | teacher 输出 `softmax(z_t / T)`，温度 T 软化概率分布，暴露类间相似度 |
| **损失函数** | `loss = α·T²·KL(log_softmax(z_s/T) ‖ softmax(z_t/T)) + (1−α)·CE(z_s, y)` |
| **超参数** | T=4.0、α=0.5、epochs 60–100、cosine 退火、batch 16、lr 1e-3、dropout 0.25 |
| **对比口径（关键）** | **唯一变量 = 是否用 teacher 软标签**：同一 student 跑 `hard-only` vs `distilled`，双 seed（42/123）取均值；固定 epoch 无早停 |

**两个任务的具体配置**：

| 任务 | teacher | student | 端侧参数量 |
|---|---|---|---|
| 8ch 二分类 | relu EEGNet（eval 77.4%） | relu / LIF EEGNet | 1650 |
| 22ch 四分类 | ELU EEG-TCNet（35,180 参数，eval 65.7%） | relu / LIF EEG-TCNet（brief 9,512 参数） | 9344 |

## 2. 核心结论（三条规律，全部双 seed 复现）

**规律一：红利集中在低标签预算，满标签中性。**

| 任务 | 100% | 30% | 10% |
|---|---|---|---|
| 8ch 二分类（relu） | ≈0 | **+5.02pp** | +5.87pp |
| 8ch 二分类（LIF） | ≈0 | **+5.10pp** | +3.70pp |
| 22ch 四分类（relu） | −0.03pp | **+7.00pp** | +5.26pp |

→ 蒸馏在「硬标签越不足」时越有用；30% 标签是红利最稳的档位。

**规律二：红利随任务难度增大。**

22ch 四分类（hard 基线 48.42%）30% 红利 +7.00pp > 8ch 二分类（基线 69.44%）的 +5.02pp。
软标签的 dark knowledge 在「任务越难、硬标签越不够」时越值钱。

**规律三：类脑化（LIF）零代价，但要热启动。**

- relu 学生 100 epoch = 57.25%；LIF **热启动** relu 权重后蒸馏 = **56.40%（追平，−0.85pp）**。
- 但 LIF **随机初始化**蒸馏只有 49.23%（surrogate gradient 训练收敛难）——「LIF 训练难」是**初始化问题**，不是蒸馏红利上限。
- 结论：**蒸馏 + 类脑两个招牌兼容**，端侧小模型（relu 或 LIF）都在少标签下吃 +5~7pp。

**边界条件（第四条，EEGMMIDB 正例+反例验证，2026-10）**：蒸馏红利（dark knowledge 传递）前提 = teacher
**显著**强于 student，且红利随「teacher − student 差距」单调（差距越大红利越大）。**正例**：EEGMMIDB 2 类
（teacher 70.4% > student 68.5%，+1.9pp）→ 30% +2.22pp 红利复现；**反例**：EEGMMIDB 4 类（跨被试天花板
~38%，teacher 36.3% < student 38.5%）→ 30% −2.78pp 红利消失。「teacher 能强多少」取决于任务精度天花板；
极低标签（10%）的正则化红利跨任务稳定（+1.5~5pp）。报告
`algorithm/蒸馏框架_可复用性验证_EEGMMIDB.md`。

## 3. 端侧闭环（蒸完怎么落地）

统一链路：**蒸馏训练 → 保存 checkpoint → BN 折叠 → 导出 C 头 → 端侧 C 推理逐位验证**。

| 链 | 脚本 | 导出 | 逐位验证 |
|---|---|---|---|
| 8ch 二分类 | `train_distill_lif_save.py` → `export_lif_surrogate_weights.py` | 1650 参数 | max\|diff\|=1.91e-06、预测一致 100% |
| 22ch 四分类 | `train_distill_4class_save.py` → `export_tcnet_snn_weights.py` | 9344 参数（TCN 8 个 LIF 位点） | **50/50、max\|diff\|=0（严格逐位一致）** |

关键点：蒸馏训出的 LIF 模型**直接走既有端侧 C 链路，无需改网络结构**——「训练端的蒸馏」和「部署端的类脑化」无缝衔接。

---

## 4. 关键坑（踩过并已解决）

1. **LIF 随机初始化蒸馏训练难**（49% vs relu 57%）→ 先训 relu 学生做热启动源，再 `--warm-start` 热启动 LIF 微调。
2. **偶核 Conv1d `padding=kernel//2` 每层输出长度 +1**（3840→3842）→ 等长用 `padding="same"`。
3. **cc 编译 `#include "xxx.h"` 优先搜 C 源码所在目录** → 验证新权重头时把 .c 也复制进 tmp，否则误 include 旧头文件导致逐位对比假失败。
4. **LIF 冒烟 `--device cpu` >60s 超时** → 冒烟直接上 `--device mps`；全量必须 background + notify_on_complete（stdout 全缓冲、中途无输出是正常的）。
