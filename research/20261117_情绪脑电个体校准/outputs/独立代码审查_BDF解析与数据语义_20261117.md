# 独立代码与数据语义审查（Hermes 侧）

2026-11-17。对 `work/` 下 FACED 与 DENS 脚本的独立审查，重点是 BDF 解析、采样解码、物理缩放、预处理、基线、视频来源与跨被试/电影拆分的正确性与泄漏。审查方式为静态读码 + 对真实 BDF 头和数据段、`stimuli.tsv` 的实证抽样验证。结论只覆盖已验证的部分，不扩展到未验证的文件或结论。

## 一、已验证正确（实证）

1. **BDF 头字段索引正确**。`field(offset,width) = head[256 + offset*n + j*width : …]` 是对的。EDF/BDF 头是「按字段交错」布局（先全部通道的 label、再全部 transducer、再全部 unit…），不是「每通道连续 256 字节块」。抽样 sub-008（32 通道，head_size 8448，250 Hz）：用脚本公式取到的 label 依次为 `Fp1 Fp2 Fz F3 F4 F7 F8 FC1 FC2 …`，与实际电极排列一致；unit 全部 `uV`；samples 全部 `250`。若误用「每通道 256 字节」的读法反而得到乱码。此点已实跑排除。
2. **24-bit 采样解码与符号扩展正确**。`v = b0 | b1<<8 | b2<<16; v = where(v & 0x800000, v - 0x1000000, v)` 符合 BDF 小端 24-bit 补码。
3. **物理缩放正确**。sub-008 前两条数据记录解码后，10 个目标通道的 uV 标准差 8.3–15.9（合理脑电量级），raw 数字值在 dmin/dmax 内、无削波。
4. **记录内通道字节偏移正确**。`offs = cumsum(ns)*3`、`width = sum(ns)*3` 与实测 data record 大小一致（sub-008 单记录 24000 字节 = 32 通道 × 250 采样 × 3 字节）。
5. **类别映射正确**。v2 脚本 `CATEGORY` 的 14 个视频编号逐一比对 `stimuli.tsv` 的 `targeted_emotion`，全部一致（anger/disgust/sadness/amusement/inspiration/joy/tenderness 各 2 部）。
6. **拆分无泄漏**。训练/验证被试不重叠（8–19 + 61–64 对 20–23 + 65–66），训练/验证视频编号不重叠（且逐影片 source_title 不重叠）。`StandardScaler` 均只在训练集拟合。交叉验证（逐人逐片留出 90 训练 1 测试）与群体先验（逐人留出 + 同视频群体均值排除本人）均无测试标签回漏。

## 二、发现的问题（附反例与影响）

### I-1 直流偏置未重参考，且未在 FACED 结论文档中显著说明
- 反例：sub-008 前 2 秒各通道 uV 均值——Fp1 −18510、Fp2 −19488、F3 −8722、O1 +4038、O2 +4752，而标准差仅 8–16 µV。这是 BioSemi 未重参考记录的典型直流偏置。
- 影响：本实验用 log 频带功率 + `welch` 默认 `detrend='constant'`，直流被去除，结果不受影响；且 `quality['dc_abs_median_uv']` 已记录该量。但「短基线校准 = 基线 log 功率相减」是功率比，**不会**去掉直流，任何后续复用原始幅度（ERP、连通性、换特征）都会被几千 µV 直流淹没。DENS 文档已写明「含直流偏置」，FACED 侧未见同等说明。
- 建议：在 FACED 结果文档补一句「信号未重参考、带 BioSemi 直流偏置，仅对频带功率特征免疫」，并说明基线减法的作用边界。

### I-2 被试选择未预注册（可复现性/透明度缺口）
- 反例：数据集 123 人。pilot 用 sub-000–007，开发用 sub-008–023 + 061–066（22 人），sub-024–031 声明保留。但 sub-032–060（29 人）与 sub-067–123（57 人）共 86 人**没有任何说明**为何排除。
- 影响：论文阶段必须给出可预注册的选择规则（如「按编号取前 N 个数据完整者」「排除缺某文件者」），否则 22/123 的取舍看起来像事后挑选，会进一步削弱本就阴性的结论的可信度。当前文档未说明这 86 人的去向或排除理由。

### I-3 README 复现顺序会产生 v1 数字，而非文档头条的 v2 数字
- 反例：README「复现顺序」先列 `faced_development_20261117.py`（v1：12 训练 + 4 验证、每人 9 视频），后列 `faced_development_v2_20261117.py`（v2：16 训练 + 6 验证、每人 7 视频）。头条的「16/6、112/42」来自 v2。
- 影响：照 README 顺序跑到 v1 会得到另一组数字，且 v1 结果未被任何文档引用，复现者会误判「脚本对不上结果」。建议在 README 标注哪个脚本产出头条数字，v1 是早期子集。

### I-4 基线窗口脆弱：首视频 onset < 4 秒会抛错
- 反例：`extract(first-4, first-1)` 中 `lo = floor((first-4)/record_s)`，若某被试首视频 onset < 4 秒则 `lo < 0` 抛 `ValueError('negative start')`。22 人未逐一确认均有 ≥4 秒前导。
- 影响：不静默出错（会显式失败），但复现前需确认全部被试满足条件。基线也是「首视频前单段 3 秒」，对整段 ~30 分钟会话无漂移校正，属已知限制，仍建议在方案文档中写明「单点基线、无会话内漂移校正」。

### I-5 质量指标计算了但没有进入头条结果
- 反例：`clipped_fraction`、`dc_abs_median_uv`、`std_median_uv` 逐试次写入 results.json，但 MAE 表未报告这些指标的分布。
- 影响：读者无法判断是否有试次被削波/伪迹污染。建议在结果文档附一张质量指标分布（按被试或按试次），或至少说明「所有试次 clipped_fraction < X、std 中位 Y」。

### I-6 FACED 评分交叉核对结果未写入 outputs
- 反例：`faced_ratings_crosscheck_20261117.py` 比对 NEMAR events.tsv 与 AMA-EEG `After_remarks.mat` 的 12 项评分，但结果 `ratings_crosscheck.json` 被 `.gitignore` 排除，且无任何 output 文档汇总其 `max_abs_difference`。
- 影响：「评分忠实转换」是后续所有 arousal 目标成立的前提，应有一条可核验的结论（如「max_abs_difference < 1e-10」）落到文档，否则评分来源可信度悬空。

## 三、结论

GPT 侧脚本的 BDF 解析、采样解码、缩放、拆分与交叉验证均无泄漏或数值 bug（已实证抽样）。上述问题集中在**透明性与可复现性**（被试选择规则、v1/v2 混淆、质量指标未汇总、直流偏置未写明），不改变「当前简单 EEG 模型未超过常数均值/群体先验」的阴性结论。下一步优先补 I-1（直流说明）与 I-2（被试选择规则），再补 I-5（质量分布）与 I-6（评分交叉核对结果），即可让这套开发脚本达到可独立复现的完整度。
